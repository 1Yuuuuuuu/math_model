# 使用论文与文献工作流

> **先读此警告。** 论文数值、实验结果、文献元数据和引用均须来自可核验的真实输入与记录，**不得伪造**。候选文献只是待审核线索，不是参考文献；未完成**人工确认**的候选不得进入正文、BibTeX 或结论。没有可用来源时，停止引用路径或只写检索计划，不能用模型记忆补全 DOI、作者、年份或证据。

## 先选择合适入口

### 当前可用性与前提

下表是 **2026-08-21 受检会话** 的静态观察，不是持续检测结果。当前运行时的 Skill 与工具列表可能变化；后续实现存在时，应以该列表核实可调用项，而非假定命令可用。

| 能力或入口 | 当前观察 | 现在如何使用 | 限制 |
| --- | --- | --- | --- |
| `cumcm-paper` | legacy Skill 目录存在 | 仅在当前运行时列出且用户显式选择时使用 `/cumcm-paper` | `cumcm_*` 运行时工具在受检会话中不可用或未确认；必须说明缺口 |
| `math-modeling-paper` | legacy Skill 目录存在 | 仅在当前运行时列出且用户显式选择时使用 `/math-modeling-paper` | 不替代未来 CUMCM 总控；不假定有联网检索后端 |
| `paper-search` | legacy Skill 目录存在，但 CLI **当前不可用** | 以用户提供的 PDF、DOI、BibTeX 或链接做离线整理，或只产出检索计划 | 不把 `paper-search` 搜索写成当前已验证命令 |
| `cumcm-orchestrator` | 规划中，未实现、未安装 | 无当前命令；见“未来分阶段工作流” | 是未来默认入口，不能冒充已可运行 |
| `literature-researcher` | 规划中，未实现、未安装 | 无当前命令；见“未来分阶段工作流” | 是未来按需文献子 Skill，不能冒充已可运行 |

当前可用性的核心前提是：有赛题、真实数据或经用户允许的材料；对文献路径，还需要用户提供可读取的材料或批准可用的检索后端。有关路由政策与完整状态，请参阅[能力矩阵](../architecture/paper-skill-capability-matrix.md)和[总体设计](../superpowers/specs/2026-08-21-cumcm-workbench-design.md)。

### 按请求选路

| 常见请求 | 默认入口 | 备选入口 | 立即产物 |
| --- | --- | --- | --- |
| CUMCM 全流程建模与论文 | 当前默认入口尚未实现；说明未来 `cumcm-orchestrator` 路线 | 用户显式选择 `/cumcm-paper`，并暴露缺失工具 | 任务拆解、模型与论文计划，不伪造运行结果 |
| CUMCM 单 Skill 写作支持 | `/cumcm-paper`（仅在当前运行时列出且用户显式选择） | 不依赖文献的论文规划 | 写作资料、待执行步骤与风险清单 |
| MCM/ICM 或其他建模竞赛 | `/math-modeling-paper`（仅在当前运行时列出且用户显式选择） | 不依赖文献的论文规划 | 通用建模论文框架 |
| 只做文献研究或补证据 | 用户提供 PDF、DOI、BibTeX 或可靠链接 | 无材料时仅形成检索式与待提供材料清单 | 候选文献表，不生成正式引用 |
| 没有后端、网络或全文 | 继续与文献无关的建模工作 | 停止引用路径并请求用户提供材料 | 明确的缺口、恢复条件与检索计划 |

“默认入口”描述的是目标架构的优先路线；在它尚未实现期间，不会静默改用 legacy Skill。用户未作选择时，先说明默认入口不可用和两项备选入口的边界。

## 使用当前可行的工作流

### 选择 legacy 论文入口

1. 用户明确选择 CUMCM 时，选择 `/cumcm-paper`；若会话未列出该入口，报告不可调用，不替换为虚构的 `cumcm_*` 工具结果。
2. 用户明确选择 MCM/ICM 或通用竞赛流程时，选择 `/math-modeling-paper`；它是兼容入口，不是未来 CUMCM 总控。
3. 先固化赛题、数据、假设、代码版本、参数和实际运行输出，再写论文。数值、图表和结论必须能回溯到这些产物。
4. 若主张需要外部证据，进入候选文献流程；否则直接形成提纲与引用清单的空白/已核验部分。

例如，用户说“用我上传的赛题和数据写 CUMCM 论文”，但没有明确选择 legacy 入口时，应先说明未来默认入口尚未实现，再请其在 `/cumcm-paper` 与不依赖 Skill 的分步规划中选择；不能把规划中的 `cumcm-orchestrator` 当作已经存在。

### 整理用户提供的文献

1. 记录用户提供材料的文件名或稳定标识、版本/下载日期、可读状态与拟支持主张。
2. 抽取可验证的题名、作者、年份、出版物、DOI/URL 与页码或章节定位；遇到冲突时保留冲突，不自行猜定。
3. 形成“候选文献”表，标明每条材料的支持边界与缺失项。
4. 将候选和拟支持主张随论文提纲提交人工确认；只有批准项才可登记来源与引用记录。

**合成示例（不代表真实论文或真实检索结果）：** 用户提供 `method-note.pdf`，文件内写有题名“示例性鲁棒优化说明”、作者“甲乙”、年份“2024”。候选表可以写为“作者/年份待人工核验、拟支持主张：参数扰动应做敏感性分析、定位：第 2 节”。它不能被写成正式参考文献，不能补造 DOI，也不能宣称该文献已证明具体模型效果。

## 为未来分阶段工作流做准备

以下流程是**规划中的未来工作流**，其中的入口和命令均不是当前已验证命令：

1. 问题与数据 → 定义待证据化主张。
2. **可选**检索 → `literature-researcher` 生成候选文献表；无后端则只保留检索计划。
3. 候选表 → 人工批准或拒绝候选与拟支持主张。
4. 批准项 → 登记来源记录与引用记录，并写入提纲。
5. 提纲与真实实验结果 → 生成论文。
6. `citation-check` → 核验每处引用、定位和支持边界。

在这一设计中，候选文献与引用清单随论文提纲在人工门 3 确认；这里的 **gate 3** 指论文审查质量门，不是额外增加的全局人工门。流程、人工门和失败关闭原则见[总体设计中的标准工作流](../superpowers/specs/2026-08-21-cumcm-workbench-design.md#标准工作流与人工确认门)。

### 在 Codex 中操作

1. 先查看当前会话的 Skill 和工具列表，确认 `/cumcm-paper` 或 `/math-modeling-paper` 是否实际列出；只选择用户明确指定且实际列出的 legacy 入口。
2. 需要文献时，先请求用户提供 PDF、DOI、BibTeX、可访问链接或明确授权的后端；当前不要运行 `paper-search` CLI。
3. 将候选、批准决定、来源定位和正文主张分别保留，直到未来的 `literature-source` 与 `citation-link` 契约和工具实现。
4. 对未实现的 `cumcm-orchestrator` 与 `literature-researcher`，只说明其为**计划命令/计划入口**，不执行也不承诺输出。

### 在 DeepSeek Harness 中操作

当前 DeepSeek Harness 没有已确认的同名论文/文献运行时入口或确定性搜索/读取 Tool。应使用同一份用户提供材料和上述人工确认记录，不把 Codex 的入口名称当成 DSH 已安装插件。

未来 DSH 适配完成后，计划以同名 Skill 消费共享契约，并通过显式配置的确定性搜索/读取 Tool 执行。网络、允许域和凭据权限必须在该阶段明确配置；在此之前，不能把 DSH 说成可自动检索或下载论文。

### 请求候选批准

在人工确认前，向用户展示可审阅的最小信息，而不是直接写入参考文献。示例为合成数据：

| 候选 ID | 元数据 | 拟支持主张 | 定位 | 当前决定 |
| --- | --- | --- | --- | --- |
| `C-01` | “示例性鲁棒优化说明”；作者/年份待核验；无 DOI | “需报告参数扰动下的敏感性分析” | 用户提供 `method-note.pdf`，第 2 节 | 待人工确认 |

可这样请求批准：“请确认是否允许把 C-01 作为关于敏感性分析方法的来源候选，并确认作者、年份与定位；若批准，它只支持该方法性主张，不支持具体实验效果。” 批准应记录候选 ID、选择、理由、时间和对应提纲版本。未获批准的源不进入正文。

## 处理失败并恢复

| 情况 | 立即处理 | 恢复条件 |
| --- | --- | --- |
| `paper-search` CLI 缺失 | 标记为当前不可用；不尝试自动安装 | 用户显式授权安装，或提供材料/获准后端 |
| `cumcm_*` 运行时工具缺失或未确认 | 停止依赖该工具的步骤，说明工具缺口 | 当前运行时确认可用，或改走人工可复现步骤 |
| 网络失败 | 保留检索式、时间与失败信息；不编造检索结果 | 网络/权限恢复后重新检索并记录版本 |
| 元数据冲突 | 将冲突字段保留为未决，不生成引用 | 用户提供权威记录，或人工确认正确条目 |
| PDF 不可获得或不可读 | 不把摘要片段当作全文证据 | 用户提供可读全文或可核验定位 |
| 文件哈希不匹配 | 停止把该文件关联到原记录 | 重新取得正确版本、记录新哈希并重新审核 |
| 来源未经批准 | 保留在候选表，不进入 BibTeX、正文或结论 | 在人工门 3 获得明确批准 |

### 安装边界

安装永不自动进行。无论是 `paper-search` CLI、未来 Codex Skill，还是未来 DeepSeek Harness Tool，均须在相应阶段由用户明确授权后才可安装或配置。安装后也应重新确认实际运行时可用性，并将搜索结果仍按候选→人工确认→来源/引用记录的路径处理。
