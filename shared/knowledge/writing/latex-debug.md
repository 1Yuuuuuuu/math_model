# 编译排错

## 是什么
LaTeX 编译把 `.tex` 源码经引擎处理成 PDF，常见环节包括字体与宏包加载、交叉引用解析、参考文献处理。中文论文用 XeLaTeX 配合 ctex 编译；报错信息记录在日志文件中，编译失败、未定义引用、缺失文件都会以结构化方式暴露。

## 为什么重要
编译是论文产出的最后一道闸门：编译失败意味着无法交稿，未定义引用会让正文中的 `第~X~节` 显示为问号，缺包会导致中途停止。能快速定位日志中的错误与警告，是稳定交付的前提。

## 常见误区
只看终端最后几行而忽略日志中的首个错误；只编译一遍就断言"引用已解析"；缺少宏包时不知所措；本机没有 Perl 却依赖 latexmk；忽略 undefined reference 警告直接交稿；把 `%`、`_`、`&` 等特殊字符裸写进正文导致编译报错。

## 在本工作台中的用法
`latex/build` 用 XeLaTeX 双遍编译（本机 latexmk 缺 Perl 不可用，故用双遍代替），解析日志中的页数、未定义引用与错误行并返回结构化报告；`latex/lint` 在编译前静态检查标签与占位标记；MiKTeX 缺包时由构建环境自动安装或手动安装后重跑。

## 一句话总结
用双遍 XeLaTeX 编译并读取结构化报告，先清错误再查未定义引用，缺包先装再跑。
