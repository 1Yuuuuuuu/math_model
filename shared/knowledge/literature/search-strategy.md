# 文献检索策略

## 是什么
检索策略回答"为了给论文主张找证据，应该怎样提出问题、生成关键词、调用后端并处理结果"。本工作台 Phase 2 只交付检索规则与候选处理约定，不实现运行时检索 Skill（`literature-researcher` 属后续阶段）；检索结果一律只是候选。

## 为什么重要
没有策略的检索会漏掉关键方法或术语变体，也可能堆出一堆无关结果。固定"问题拆解 → 关键词生成 → 后端查询 → 候选整理"的流程，能让检索可复现、可回溯，并让每条候选都挂到具体的待证据化主张上，为人工确认做准备。

## 检索问题拆解

把论文中需要外部证据的主张拆成可检索的子问题，一条主张对应一个或几个检索问题：

1. 列出需要证据的主张（方法、基线、数据、局限性等），例如"该方法在扰动下的表现需要敏感性分析支持"。
2. 把每一条主张改写为可检索的问题：方法类问题（"用 X 方法求解 Y 问题"）、对比类问题（"X 与 Y 在 Z 数据集上的对比"）、数据类问题（"Z 数据集的来源与口径"）、局限性类问题（"X 方法的已知局限"）。
3. 每个检索问题记录：拟支持主张、检索时间、使用的关键词与后端，便于失败后重试与回溯。

## 中英文关键词生成

每个检索问题至少生成一组中文关键词与一组英文关键词，并包含同义词、缩写与术语变体：

- 中文关键词：如"线性规划""整数规划""灰色预测""层次分析法""熵权法"。
- 英文关键词：如 `linear programming`、`integer programming`、`grey prediction`、`AHP`、`entropy weight`。
- 术语变体：同一概念的不同写法，如 `grey`/`gray`、`analytic hierarchy process`/`AHP`、"时间序列"/`time series`、`TS`；同义词，如 `optimization`/`programming`（在运筹语境）、`forecast`/`prediction`。
- 变体来源：从问题本身的术语、领域惯用简称、以及已有候选文献的关键词中提取；不得编造不存在的检索结果来凑关键词。

## 后端查询参数

**前提：后端必须先经用户明确授权。** 当前会话不得假定 `paper-search` 或 `runtime-search` 后端可用；没有已授权后端时，只产出检索计划与关键词表，不伪造检索结果。已授权后端可用时，查询参数至少包含：

- `query`：检索式（关键词及其组合）；
- 时间范围（`year` 起止）；
- 语言（中文/英文或全部）；
- 排序与返回条数（如按相关性排序、`limit` 条）；
- 结果字段（标题、作者、年份、出版物、DOI、URL）。

检索返回的每条结果登记为候选（`verification_status = candidate`），记录 `retrieval_backend`、`retrieved_at` 与 `canonical_url`；网络失败时保留检索式、时间与失败信息，不编造结果。

## 候选用途：仅候选，非正式引用

检索产出的一切结果都只是**候选**，不是正式引用。沿用 Phase 0A 路由政策：候选须经人工确认，才能在人工门 3"确认论文提纲"进入正式引用（`literature-source.verification_status = approved` 并登记 `citation-link`）。候选未经确认不得写入 BibTeX、正文或结论；没有可用来源时停止引用路径或只写检索计划，不能用模型记忆补全 DOI、作者、年份或证据。

## 一句话总结
拆解检索问题、生成中英文关键词与变体、在用户授权后端上查询并记录参数；所有结果仅作候选，未经人工确认不得成为正式引用。
