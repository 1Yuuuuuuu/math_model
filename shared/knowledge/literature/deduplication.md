# 文献去重规则

## 是什么
去重是把检索到的候选文献按确定性规则分组，使同一条文献的多个来源记录归入同一组，避免同一文献在候选表、来源登记与引用清单中被重复计数或重复引用。去重只负责"归组"，不负责"裁决"：组内的元数据冲突必须保留并由人工核验，不得静默合并。

## 为什么重要
同一篇论文可能以不同大小写、不同排版、不同 URL 或不同收录页被多次检索到。没有确定性分组，候选表会出现重复条目，人工确认门（人工门 3"确认论文提纲"）看到的候选数量虚高，且同一文献可能被赋予两套互相矛盾的元数据，最终污染来源记录与引用定位。

## 三条确定性分组规则

去重按"字段优先级"为每条记录计算一个分组键，**只取第一个可用字段**；键相同则归入同一组。优先级与规范化方式必须与 `tests/knowledge/test_literature_knowledge.py` 中的参考实现 `group_candidates` 完全一致，测试代码即规则契约。

1. **DOI 分组（优先级最高）**：记录存在 `doi` 字段时，分组键为 `doi:` + 小写化后的 DOI（如 `doi:10.1000/abc`）。DOI 比较不区分大小写；`10.1000/ABC` 与 `10.1000/abc` 视为同组。
2. **规范化标题分组**：记录无 `doi` 但有 `title` 时，分组键为 `title:` + 规范化标题。规范化步骤：先做 Unicode NFKC 归一化，再转小写，最后删除所有非单词字符与下划线（等价于正则 `[\W_]+` 替换为空），即去掉空格、标点与连字符。`"A Novel Method"` 与 `"A  Novel  Method!"` 都规范化为 `anovelmethod`，归入同组。
3. **来源标识（URL）分组**：记录既无 `doi` 也无 `title`、但有 `url` 时，分组键为 `url:` + 规范化 URL。规范化步骤：删除 `#` 片段及其后内容（去掉锚点/片段），再去掉结尾处的 `/`。`https://example.org/paper` 与 `https://example.org/paper/` 视为同组。

**边界与例外：**
- 三条字段都没有（无 DOI、无标题、无 URL）的记录不参与分组，原样保留，等待人工补全标识后再去重。
- URL 的默认端口归一（如 `:443`、`:80`）**未纳入**当前确定性契约，参考实现不做该处理；若未来要加入，必须与参考实现和测试同步更新，不得只改文档。
- 分组只使用上述三个字段，不比较作者、年份或出版物；那些字段用于组内冲突核验（见下）。

## 冲突处理：保持候选，人工核验，不得静默合并

同组内出现以下任一情况即为**元数据冲突**，必须把该组所有记录保持在候选状态（`verification_status = candidate`），标记"待人工核验"，并把冲突字段原样列出：

- 作者列表不一致（如作者顺序不同、人名不同、一个记录缺作者）；
- 年份不一致；
- 出版物/来源库不一致（`venue_or_repository` 不同）；
- 同 DOI 但标题或作者不同（可能指向版本差异或错误元数据）。

冲突处理铁律：**不得静默合并**。不允许程序自动挑选"看起来更完整"的一条覆盖其他条，不允许把两条记录的作者或年份拼接成一个"合成元数据"，也不允许凭模型记忆补全缺失字段。冲突记录保持候选状态，直到人工核验出权威条目并做出明确决定（批准或拒绝）。

## 去重流程步骤

1. 汇总候选文献记录（每条至少含 `id` 与可用的 doi/title/url 之一）。
2. 按上述三条规则计算分组键，形成确定性分组。
3. 对每个组：若组内只有一条记录，直接保留。
4. 若组内多条记录且核心元数据（标题、作者、年份、出版物）完全一致，视为重复条目，合并为一条候选，并保留合并前所有来源标识与定位供溯源。
5. 若组内存在元数据冲突，保持候选状态，标记"待人工核验"，随候选表一并提交人工确认。
6. 只有经人工确认的组才能进入后续来源登记；去重结果只影响候选表，**不改变** Phase 0A 路由政策——候选未经人工确认不得成为正式引用。

## 一句话总结
按 DOI → 规范化标题 → 规范化 URL 的确定性顺序归组；组内元数据冲突保持候选并交人工核验，绝不静默合并。
